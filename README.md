# NotificationGuard / 通知管家

基于 **libxposed API 102** 的 LSPosed 通知渠道管理模块。界面使用 KernelSU 同款 **Compose + Miuix**。

当前是首个实验版本。构建通过不等于实机 Hook 已验证；系统更新后需要重新验证适配。

## 功能

- 按用户空间、应用、通知渠道设置拦截规则。
- 通知长按菜单加入“渠道拦截”，可设置拦截及独立的状态栏图标隐藏。
- 保留通知栏中的通知，仅过滤状态栏图标；图标过滤发生在按应用去重之前。
- 统计发送尝试、模块拦截和已有通知更新；支持今日、7 天、30 天和累计排行。
- 引导页及设置页提供一键开启全部 App 通知，包括系统 App、通知权限、渠道组、已有渠道及可用的澎湃媒体通知总开关。
- 修改前备份通知设置，逐项检查结果，失败项不会报告为成功；可恢复备份。
- 不保存通知标题、正文、附件或通知对象，不联网分析通知。

## 使用

1. 安装 Actions 构建的 APK。
2. 在支持 API 102 的 LSPosed 中启用模块，作用域为 `android` 和 `com.android.systemui`。
3. 重启手机使系统 Hook 加载。模块不自动重启或修改通知开关。
4. 检查“设置”中的系统通知服务和 SystemUI 状态，刷新渠道。
5. 在渠道页面设置规则，或长按通知进入“渠道拦截”。

恢复系统通知权限可能立即产生通知、声音和振动。操作前确认模块已连接，并先设好拦截规则。

## 行为与限制

- 发送尝试不是成功展示数。系统拒绝的发送请求仍可能计入尝试，模块拦截数只计算模块主动阻止的请求。
- 更新依据系统中是否已有相同通知判断。每次真实 App 发送均计入尝试；只 Hook 一个最深发送入口，不重复计算内部重入。
- 统计仅保存按日期、应用、用户和渠道聚合的整数。计数约每 5 秒批量落盘，异常关机可能丢失尚未提交的计数。
- 没有发送请求就无法记录。App 因检测到渠道关闭而不发送的事件不可补回。
- 常驻服务已经显示的通知不会被直接取消，以免干扰服务；可以隐藏其状态栏图标。新发送请求仍遵循渠道拦截规则。
- 一键开启不会关闭勿扰、调整声音与振动、打开 App 内服务器推送订阅，也不会复活已删除的渠道。系统固定权限、不可访问用户空间等会报告失败。
- 恢复针对备份中的通知开关及渠道配置，不保证恢复 Android 权限的全部审计标志；备份后新建的渠道不会删除。失败项保留备份，重复开启不会覆盖最初备份。
- 第一版适配直接依据本机提取的 SystemUI 与通知服务入口，不承诺所有 Android/澎湃版本通用。找不到已验证签名时不启用对应 Hook；运行出错时尽量保持原系统行为。
- 模块升级暂不使用热重载，需要重启。当前未加入自动营销识别或关键词规则。

## 安全与结构

`system_server` 和 SystemUI 通过受 UID 检查的 ContentProvider 与模块通信。其他 App 无法读写规则、统计和备份。任务仅允许模块自身创建，系统进程执行；通知 Hook 路径不进行数据库或 Binder IO。

系统 APK、系统 JAR、反编译代码、签名密钥均不包含在公开仓库。备份只序列化 NotificationChannel / NotificationChannelGroup 设置，不包含通知内容。

## 构建

GitHub Actions 使用 JDK 17、Gradle 8.13、Android SDK 36、Kotlin 2.3.20 和 Miuix 0.8.8，运行单元测试、Lint 并构建签名 APK。下载 `NotificationGuard` artifact。

仓库 Secrets：

- `SIGNING_KEY_B64`：PKCS12 签名文件的 Base64。
- `SIGNING_PASSWORD`：密钥库和私钥密码。

签名别名为 `notificationguard`。PR 只构建 Debug APK，不暴露正式签名。正式构建保持固定签名，可以覆盖升级。

## 实机验收

- 两个渠道：拦截其中一个，另一个正常展示；发送次数、拦截次数正确。
- 同一个常驻通知连续更新：尝试与更新增加，不被算成内部重复发送。
- 同一 App 的常驻渠道隐藏后，通知栏仍在，其他未隐藏渠道仍可产生状态栏图标。
- 长按菜单保存规则后，图标立即刷新；解除隐藏后恢复。
- 系统关闭的渠道在恢复后可以由模块拦截并计数。
- 一键开启、失败报告与备份恢复；进程中断后不自动续执行危险任务。
- 普通 App 调用 Provider 被拒绝；数据库和日志不包含通知正文。

以上实机验收尚未完成。请在主力机启用系统作用域前保留 LSPosed 的禁用/救援方式。
